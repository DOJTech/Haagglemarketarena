# Deploy Haggle: GitHub, then Render, then Netlify

Netlify cannot run this game server (it hosts web pages and short functions, not a always-on server with a database).
So: **Render runs the server and database, Netlify serves the pages and forwards `/api` to Render.**
Because the browser only ever talks to your Netlify address, there are no cross-site problems.

## 1. GitHub (private repo)
1. On GitHub create a **private** repository, for example `DOJTech/haggle`. Turn on two-factor sign-in for your account.
2. In this folder:
   ```
   git init
   git add .
   git commit -m "Haggle 1.0.0-beta"
   git branch -M main
   git remote add origin https://github.com/DOJTech/haggle.git
   git push -u origin main
   ```
3. Repo Settings > Code security: turn on Dependabot alerts and Secret scanning.
4. Never commit `.env` or any secret. (`.gitignore` already blocks `.env` and `node_modules`.)

## 2. Render (server + database)
1. Render > New > Blueprint > pick your repo. It reads `render.yaml` and creates the server `haggle-api` and database `haggle-db`.
2. When it asks for `ALLOWED_ORIGINS`, enter your future Netlify address, e.g. `https://haggle.netlify.app` (add a custom domain later, comma separated; `https://` and no path). You can change it afterwards in Environment. **The server will not start in production if this is missing or malformed.**
3. Wait for deploy. Copy your server address, e.g. `https://haggle-api.onrender.com`.
4. Open the service > Environment and copy the generated `ADMIN_KEY` (this is your owner key). Keep `SEED_SECRET` private and never change it casually: changing it changes every future daily market.
5. **Owner second factor (required).** On your own computer run `npm run make-owner-secret` (add `-- --key` if you also want a fresh `ADMIN_KEY`). It prints a secret. Add it on Render as `ADMIN_TOTP_SECRET` and type it into an authenticator app on your phone ("enter a setup key"). Save the secret in a password manager. The production server **will not start** without it. Your `render.yaml` is not in this update, so if you use the blueprint add these under `envVars`:
   ```
   - key: ADMIN_TOTP_SECRET
     sync: false
   ```
   (`sync: false` makes Render ask you for the value instead of storing it in GitHub.) Turn on two-factor sign-in on your Render account too: anyone who controls it can read both the key and this secret.

## 3. Netlify (pages)
1. Edit `netlify.toml` in your repo: replace `YOUR-RENDER-SERVICE` with your Render service name (so the line reads `https://haggle-api.onrender.com/api/:splat`). Commit and push.
2. Netlify > Add new site > Import from Git > your repo.
3. Build command: leave empty. Publish directory: `public`.
4. **Environment variables on Netlify: none.** Every secret lives on Render only.
5. Deploy. If your Netlify address differs from step 2 of Render, update `ALLOWED_ORIGINS` on Render to match.

## 4. Verify (5 minutes)
1. Open your Netlify address. The header should show "N playing now, N today, N players". Play a day.
2. Real-address check. First sign in as owner (use your own address, key and the current 6-digit code; the `Origin` header is required):
   `curl -s -X POST https://haggle.netlify.app/api/admin/login -H "content-type: application/json" -H "Origin: https://haggle.netlify.app" -d '{"key":"YOUR_ADMIN_KEY","code":"123456"}'`
   Copy the `token` from the reply, then:
   `curl -H "x-admin-token: THE_TOKEN" https://haggle.netlify.app/api/admin/ip`
   `seenAs` must be YOUR public address (search "what is my IP"), not a Netlify or Render address. If it is wrong, change `TRUST_PROXY` on Render (try 2, then 3) and check again. Without this the per-network limits would treat every player as one person.
3. Open `https://haggle.netlify.app/#owner`, tap Metrics, enter `ADMIN_KEY` and the current code from your authenticator app. The session lasts 30 minutes. Recent owner actions are listed at `/api/admin/audit` (same token header).
4. Replace the [brackets] in `public/privacy.html` and `public/terms.html`, and have a lawyer review them.

## Environment variables (Render only)
| Name | Required | What to put |
|---|---|---|
| DATABASE_URL | yes | Filled automatically by the blueprint |
| NODE_ENV | yes | `production` |
| SEED_SECRET | yes | Generated by the blueprint (16+ characters, secret) |
| ADMIN_KEY | yes | Generated by the blueprint (20+ characters in production, secret) |
| ADMIN_TOTP_SECRET | yes | From `npm run make-owner-secret`. The server will not start in production without it |
| ALLOWED_ORIGINS | yes | Your Netlify address(es), comma separated, `https://` form. The server will not start in production without it |
| TRUST_PROXY | yes | `2` (Netlify then Render). Verify with step 4.2 |
| RATE_MAX | no | Requests per network per minute, default 600 |
| MIN_RANK_MS | no | Minimum milliseconds for a ranked week, default 60000 |
| MIN_REPORT_N | no | Finished games per group before a brand report shows numbers, default 30 |
| DB_SSL_STRICT | no | Set to `1` to verify the database's certificate. Try it, then check the site still connects. If not, remove it |
| RANKED_NEEDS_ACCOUNT | no | Leave unset. `0` is for local test suites only and the production server refuses it |
| REGISTER_PER_IP_DAY / REGISTER_PER_HOUR_ALL | no | New accounts per network per day (default 20) and overall per hour (default 300). Many phones share one mobile address, so raise the first if real players are refused |
| LOGIN_PER_IP_15MIN / LOGIN_FAILS_PER_USER_15MIN | no | Sign-in attempts per network (default 40) and wrong passwords per username (default 10) per 15 minutes |
| START_PER_PLAYER_HOUR / START_PER_IP_HOUR / NEW_DEVICES_PER_IP_HOUR | no | Games started per player (60), per network (300), and new devices per network (200) per hour |
| SESSION_DAYS / ADMIN_SESSION_MIN | no | Player sign-in lifetime in days (14); owner session in minutes (30) |

## Free-tier cautions
- A free Render server sleeps when idle; the first visit after a quiet spell can fail or take about a minute. Use a paid plan before launch, or ping `https://haggle.netlify.app/api/stats` every 5 minutes with a free uptime monitor.
- Set up backups and an uptime monitor before real users arrive: see `docs/BACKUPS_AND_MONITORING.md`. Nothing is backed up automatically on a free plan.

## Run the tests locally
First, with no database needed: `npm run test:unit` (engine, security helpers, and the server wiring against a fake database).

Then install Postgres, create a **scratch** database, and run the real-stack suites:
1. `DATABASE_URL=postgres://... node test/accounts.test.js` (starts its own server; covers accounts, sessions and the owner second factor on real SQL)
2. `DATABASE_URL=postgres://... PORT=3055 RANKED_NEEDS_ACCOUNT=0 MIN_RANK_MS=1000 RATE_MAX=100000 npm start` and in another terminal `node test/anticheat.test.js`, `node test/moderation.test.js`, `node test/features.test.js`, `node test/campaigns.test.js`, `node test/security.test.js`, `node test/load.test.js`. (`RANKED_NEEDS_ACCOUNT=0` lets these older suites rank with a bare device ID. Production refuses that setting.)
